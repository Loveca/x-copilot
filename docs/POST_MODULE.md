## 1. 需求原文（PROJECT.md §22）

```text
✍️ Generate Post

读取：
  - 当前 Tweet
  - 当前页面若干高互动 Tweet
  - 用户指定主题

生成：
  观点型 / 反向型 / 热点型 / 短帖 / Thread 开头

点击 [填入] → 自动填入 X Compose。仍然：不自动发送。
```

产品定位（`PROJECT.md` §1）：**降低"我想参与讨论，但不知道说什么"的认知成本**；后续扩展里的第一项就是「AI 帖子生成」。

红线不变（`PROJECT.md` §32 / ARCHITECTURE.md §6）：不自动发帖、不自动评论、不自动点赞关注、不批量操作。**只有用户本人可以发送内容。**

## 2. 与回复模块的差异

| 维度 | 回复生成（Phase 1） | Post Copilot（Phase 2） |
|---|---|---|
| 内容来源 | 当前 Tweet（必须有） | 用户主题 / 当前 Tweet / 页面高互动 Tweet（**可以完全没有推文**） |
| 目标输入框 | Reply composer | **主 Compose 发帖框** |
| 风格体系 | 观点 / 补充 / 反向 / 简短 / 水贴（回应别人） | 观点型 / 反向型 / 热点型 / 短帖 / Thread 开头（表达自己） |
| Prompt | 严格贴合原推，不复述 | 无原推约束，需要自己立论 |

**两套风格必须分开配置**：`回复风格` 与 `发帖风格` 是不同维度，不能复用同一份配置。

## 3. 可复用 vs 需新建

**直接复用**：悬浮球 + Panel、流式生成与逐条渲染、会话缓存、`fill.ts` 的合成 paste 写入策略、设置页分区架构、风格配置的数据模型（排序 / 数量 / 开关）、Provider 的 400 降级与图片能力。

**需要新建**：

| 工作 | 风险 | 状态 |
|---|---|---|
| 主 Compose 检测 + 填入 | 🔴 高 | M0 Spike 中 |
| 面板「回复 / 发帖」模式切换 | 🟡 中 | 未开始 |
| 发帖 Prompt + 发帖风格配置 | 🟢 低 | 未开始 |
| 高互动 Tweet 抓取 | 🟡 中 | 未开始 |
| Thread 开头 / 完整 Thread | 🟢 低 | 未开始（spec 只要求"Thread 开头"一条） |

## 4. M0 Spike：主发帖框能不能通

**为什么先做这个**：回复模块当年把「无头验证 fill composer」排在所有任务之前（ARCHITECTURE §4 Task 0）。主发帖框的检测与写入是 Phase 2 最高风险项——X 有多种 composer（首页时间线、Modal、引用、回复），它们共用同一个 `tweetTextarea_*` testid；而且只把文字塞进 DOM 不算成功，**必须让 X 自己的状态更新**（Post 按钮从 disabled 变可用）。通不过这一步，后面全是空中楼阁。

**结果：已通过（2026-09-15）**。首页时间线发帖框与弹窗内发帖框两种变体都验证成功，填入后 X 的 Post 按钮正常激活。

**已实现**：

- `selectors.ts`：新增 `postComposer`、`postButton`、`POST_COMPOSER_KEYWORDS`
- `composer-detector.ts`：`findPostComposer()` 按「排除回复框 → 弹窗内优先 → aria-label 像 Post text → 兜底第一个」的顺序判定；`isPostButtonEnabled()` 用于判断 X 是否认账
- `fill.ts`：`fillComposer`（与 `fillReplyComposer` 同一套策略，去掉 reply 限定）
- 面板：开发者选项打开时多一个「Spike：测试填入主发帖框」按钮，结果通过 toast + Console 的 `[X Copilot] post composer spike` 输出

**验证步骤**：

1. 设置页 → 插件信息 → 开发者选项 → 打开「显示生成耗时信息」
2. 打开 x.com **首页**（时间线上有发帖框）
3. 点悬浮球打开面板 → 点「Spike：测试填入主发帖框」
4. 看结果：
   - toast 「已填入，Post 按钮已激活」→ ✅ Spike 通过
   - toast 「文字进去了，但 Post 按钮仍禁用」→ ⚠️ DOM 成功但 X 状态没更新，需要换写入策略
   - toast 「未找到主发帖框」→ 选择器需要调
5. 另外在**点开发帖弹窗**的状态下再测一次（弹窗内的 composer 是另一个变体）
6. 测试完记得删掉那句测试文字

Console 里会打出 `testId` / `ariaLabel` / `filled` / `postButtonBefore` / `postButtonAfter`，排查时把这行发出来最省事。

## 5. M1：Post Copilot v1（已实现）

- **模式切换**：面板顶部「回复 / 发帖」分段控件。检测规则：识别到推文 → 回复模式；时间线上没有具体推文 → 发帖模式。手动切换会清空上一模式的结果（回复候选与发帖草稿不能混）
- ⚠️ **已识别到具体推文时「发帖」直接置灰、点击无反应**（详情页 / 回复弹窗）。理由：详情页没有发帖入口，在这里谈"写自己的帖子"在交互上是断裂的——先这样收敛，等有更合理的逻辑（比如自动打开 X 的发帖弹窗）再改
- **三种输入源全部接上**（按用户选择）：
  - 用户主题：复用意图输入框
  - 当前 Tweet：作为**灵感**（prompt 里明确写了"不要回复它，写一条独立的帖子"）
  - 页面高互动 Tweet：`collectTimelineTweets(5)` 扫描当前页面可见帖子，按 点赞+回复+转推 排序取前 5 条
- **发帖风格**：`uiConfig.postStyles` 独立配置（观点型 / 反向型 / 热点型 / 短帖 / Thread 开头），与 `styles` 完全分离
- **生成**：`GenerateOptions.mode = 'reply' | 'post'`，provider 按模式选 prompt（回复强调贴合原推，发帖强调自己立论、不许编造用户没给的事实）
- **填入**：发帖模式用 `findPostComposer()` + `fillComposer()` 写主发帖框；回复模式仍走原来的回复框
- **缓存键带模式**：`模式::tweetId::意图`，避免同一条推文的回复结果与发帖草稿互相覆盖

## 8. V1 增强：三个「零依赖」内容源（设计稿 · 待确认）

> 2026-09-15 提出。要解决的是发帖模式最实际的困境：**用户打开面板时常常没有明确想说的**。
> 「回复生成」解决"别人说了什么、我接一句"；发帖要解决"我自己想说什么"。但现在三个输入源（用户主题 / 当前推文 / 时间线高互动帖）**全部要求用户先有想法**，没有想法就卡住——而这恰恰是 `PROJECT.md` §1 要解决的"不知道说什么"。

### 8.1 范围划分

**V1（本次做）** —— 共同点：只依赖「当前页面上有什么」或「本地库里有什么」，**完全不需要理解这个账号是谁**。

| # | 内容源 | V1 行为 | 数据来源 | 需要模型吗 | 难度 |
|---|---|---|---|---|---|
| 1 | 水贴（三件套） | 点一下出 3 条成品短句，一键填入 | 模型生成（不依赖页面状态，随时能用） | ✅ | 低 |
| 2 | Feed 热帖 | 列出当前可见 Feed 互动 Top 5，点一条设为「选题」 | 页面 DOM（复用 `collectTimelineTweets`） | ✅ 生成时才用 | 低 |
| 3 | 趋势 | 列出 X 右侧栏趋势话题（≤10），点一个设为「选题」 | 页面 DOM（右侧栏） | ✅ 同上 | 低 |

**V2（本次不做）** —— 共同点：都依赖「这个账号是谁、平时聊什么」。

| # | 内容源 | 为什么放 V2 |
|---|---|---|
| 4 | 账号领域方向推荐 | 要读用户历史发帖做画像，没画像无从推荐 |
| 5 | 热点 + 专业视角结合 | 依赖 #4（先知道你的专业领域，才谈得上"专业视角"） |
| 6 | 同领域爆款结构模仿 | 依赖 #4，且要抓同赛道账号数据，成本最高 |

> 这三个的真实价值**没有验证过**。V1 先用零依赖的三类把功能跑起来、拿真实反馈，再决定要不要往"账号画像"这个更重的方向投。

### 8.2 三个内容源的技术口径

#### 8.2.1 水贴（三件套）

**是什么**：三类"随时能发、跟当下无关"的成品短句，一次各出一条。

| 类别 | 定义 | 示例 |
|---|---|---|
| 顶级认知 | 一句反直觉、但站得住的判断 | 「复利最难的地方不是收益率，是你能不能不打断它。」 |
| 冷知识 | 一个具体、可核对的小事实 | 「章鱼有三个心脏，血液是蓝色的。」 |
| 扎心真相 | 戳痛点但不说教的实话 | 「大多数人不是没时间，是把时间给了不重要的东西。」 |

**产出方式：模型生成**（用户 2026-09-15 决定）。点一下即发一次请求，与「生成帖子」是两条独立链路——要的是**成品句**，不是围绕主题的草稿。

- 新增 `buildIdeaPrompt()`（`lib/llm/openai-compat.ts`），固定三类各一条；产物走现有流式链路，`partial` 逐条渲染 / 缓存 / 填入**全部复用**
- 候选的 `style` 字段直接放类别名（顶级认知 / 冷知识 / 扎心真相），刚好复用现有按风格分组的候选卡
- **不参与 `postStyles`**：那是"怎么说"的维度（观点型 / 反向型…），这是"说什么"。两套互不干扰
- 用户写了意图（intent）时一并带上，让三件套围绕这个点写
- ⚠️ **冷知识的事实风险由 prompt 兜**：`buildIdeaPrompt` 明确要求「只给你确信为真、可核对的事实；不确定就换一个，绝不猜」。仍然建议用户发送前扫一眼——这类内容出错的代价是账号可信度

#### 8.2.2 Feed 热帖

- **数据**：复用已有的 `collectTimelineTweets(limit)` —— 扫当前页面所有 `article[data-testid="tweet"]`，按 `点赞 + 回复 + 转推` 排序。**只取已渲染的**：不滚动加载、不发额外请求。
- **展示**：每条显示 `@handle · 前 80 字 · ♥ 1234`。
- **点选后**：设为「选题」（面板上一个可清除的 chip），生成时作为 **inspiration** 传入（`buildPostPrompt` 已有对应段落："不要回复它，写一条独立的帖子"）。
- ⚠️ **口径注意**：现在 `runGenerate` 是无条件把 `collectTimelineTweets(5)` 塞进 prompt 当隐式背景的（用户看不见）。V1 **保留隐式背景**（给「热点型」提供语境，成本为零）**并新增显式点选**，两者不冲突。

#### 8.2.3 趋势

- **数据**：新增 `lib/content/x/trend-detector.ts` → `collectTrends(limit = 10)`，读 X 首页右侧栏**已渲染**的趋势模块。
  - 容器：`[data-testid="sidebarColumn"]`
  - 每条：`[data-testid="trend"]`
  - ⚠️ **选择器要拿真实页面实测校准**（X 改版频繁，且这个没有现成代码可抄）
- **点选后**：同热帖，设为「选题」。
- **降级路径（必须处理）**：
  - 窗口太窄时 X 不渲染右侧栏 → 提示「没读到趋势栏，把窗口拉宽再试」
  - `/explore/tabs/trending` 趋势页是同一套选择器，可作为备用入口

### 8.3 交互

发帖模式下的面板结构（2026-09-15 按设计稿调整过一次布局与命名，★ = V1 新增）：

```
[ 回复 | 发帖 ]                  ← 两个独立胶囊，当前项黑底白字
──────────────────────────
（灵感推文卡：仅当有来源推文时）
[ 意图 textarea ]                ← 无边框，靠占位文字与留白区分
[ 生成帖子 ]                     ← 黑底、圆角 12px
★ [ 选题：@sama「…」 ✕ ]        ← 选了 Feed热帖 / 热点才出现；单值，可清除
★ 灵感来源
★ [水贴] [Feed热帖] [热点]  ⟳换一批   ← 带图标，默认选中「水贴」；⟳ 仅水贴下有
★ （水贴：3 条成品，各来一条；Feed热帖：列帖子；热点：列话题）
──────────────────────────
★ 候选列表                      ← 「生成帖子」的结果；一条一行，点整行填入发帖框
```

#### 8.3.1 水贴的最终交互规则（2026-09-15 定稿）

| 规则 | 行为 |
|---|---|
| **何时出三条** | 面板打开、或切到「水贴」时**自动**出一批：顶级认知 / 冷知识 / 扎心真相**各一条**（不会同类堆叠） |
| **沿用还是重抽** | 已有三条就**沿用**（`ideaItems` 非空就不发请求）；同一次会话反复开关面板不会重复烧 token |
| **换一批** | 右侧 `⟳ 换一批` —— 三条**同时**重抽，仍然各来一条 |
| **点其中一条** | 填进**面板上方的输入框**（当"引子"，可再编辑、可再点「生成帖子」让模型展开写） |
| **点完列表还在吗** | **在**。不消失、不替换，可以反复点另外两条**覆盖**输入框内容；刚点过的那条右侧显示 ✓ |
| **生成失败** | 自动尝试**只做一次**（`ideaAttemptedRef` 守卫），失败后不再自动重试，避免对着同一个错误打转；用户点「换一批」可手动重来 |

**为什么填进面板输入框而不是 X 发帖框**：这三条是**引子**不是成品。填进面板后用户可以改、可以接着点「生成帖子」让模型围绕它展开成完整帖子。真想要"点完就能发"的成品，用下面「生成帖子」出来的候选（点整行直接进 X 发帖框）。

**为什么结果不进缓存**：水贴的"沿用"靠 `ideaItems` 是否为空判断，不走 `cacheRef`。换一批 = 强制重发请求，与缓存语义相反。

**两个列表互不干扰**：水贴三件套写进 `ideaItems`（灵感来源区下方），「生成帖子」的结果写进 `replies`（下方候选区）。点「生成帖子」不会把水贴三条冲掉，反之亦然。

| 来源 | 点一下之后 |
|---|---|
| 水贴 | 三个来源里**唯一自动出内容**的：切过来就有 3 条（各来一条），点任意一条填进上方输入框；`⟳ 换一批` 重抽 |
| Feed热帖 | 展开当前页面互动最高的 5 条，点一条 → 变为「选题」chip，**不自动生成**，等用户点「生成帖子」 |
| 热点 | 展开右侧栏话题列表，点一个 → 变为「选题」chip，同上 |

**候选展示两套并存**（2026-09-15 用户明确选定，不要合并）：

| 模式 | 组件 | 样式 |
|---|---|---|
| 回复 | `ReplyCard.tsx` | **按风格分组的黑边卡**（1px #0f1419 + 黑底白字徽章 + 独立「填入」按钮） |
| 发帖 | `CandidateRow.tsx` | **一行一条**（小字风格标签 + 正文 + `›`，点整行填入，已填变 ✓） |

起因：3760631 按发帖设计稿把候选从卡片改成列表行，但组件是两种模式共用的，回复模式被连带改掉、观感变差。用户选择"两套就两套"——回复回退成卡片，发帖保持列表行。`styles.ts` 里 `.xc-card` 系与 `.xc-cand-row` 系是独立两段，改一边不影响另一边。

**为什么 Feed热帖 / 热点选中后不自动生成**：与已确定的行为一致（发帖入口只弹面板、不自动生成），把"要不要现在生成"留给用户；选错话题也不会白烧一次请求。

**为什么水贴是例外**：它没有"选一条"这个环节，语义就是"给我几句现成的"，切到这个 tab 本身就是明确意图。且它填的是**面板输入框**（引子），不是直接产出要发的帖子，风险低。

**选题是单值**：任何来源点选都**替换**它；切换来源不清除选题，只有 ✕ 或选新的才变。

### 8.5 与现有体系的关系（避免打架）

发帖现在有两个维度：**意图**（`intent`，用户想说的点）和**风格**（`postStyles`，怎么说）。
V1 新增两个维度，四者互不替代：

| 维度 | 回答的问题 | 来源 | 状态 |
|---|---|---|---|
| intent | 我想说什么？ | 用户手输 | 现有 |
| postStyles | 用什么口吻说？ | 设置页 | 现有 |
| ★ topic | 围绕**哪个话题**说？（可以没有具体观点） | 热帖 / 趋势 点选 | 新增 |
| ★ idea | 直接给我一句**话头**，我懒得想 | 水贴三件套（模型生成） | 新增 |

prompt 优先级：`intent`（用户明确想法）> `topic`（选题）> 只有风格时自由发挥。
注意 `idea` 不进 prompt —— 它是**填进 intent 输入框**的，用户点「生成帖子」时才以 intent 的身份生效。

**命名已定**：面板入口叫「**水贴**」，与回复风格里的 `casual`（也叫「水贴」，指回复别人的客套互动句）区分开。文档提到需求出处时仍可写"水贴三件套"。

### 9.1 三条铁律

| 铁律 | 含义 |
|---|---|
| **两轴分离** | 灵感来源（**聊什么**）与风格库（**怎么说**）是两个独立、正交的维度，**绝不合并成一套标签体系** |
| **绝不自动发送** | 候选只填入 X 原生发帖框，由用户自己检查、修改、点 X 原生的「发帖」按钮。插件全程不代替用户点击发送 |
| **命名不冲突** | 发帖灵感 / 发帖风格 / 回复风格是三套独立命名。回复风格里的「水贴」≠ 发帖灵感里的「随便聊聊」，不混用 |

### 9.2 状态机：A（选灵感）→ B（已生成）

面板**从上到下**的元素顺序固定为：**灵感来源 → 输入框 → 生成按钮**（操作路径与视觉顺序一致）。

| | 状态 A（未生成 / 正在选） | 状态 B（已生成过至少一次） |
|---|---|---|
| 1 | 灵感来源区块（分类 Tab + ⟳ 换一批 + 当前分类候选列表） | 一行「**‹ 换个思路（重新选灵感）**」入口 |
| 2 | 输入框（placeholder：想发点什么？） | 输入框保留刚才用于生成的文字，仍可编辑 |
| 3 | 「**生成帖子**」按钮 | 「**重新生成**」按钮 |
| 4 | — | 候选列表（按风格库生成的若干条） |

- 状态 B 点「‹ 换个思路」→ 展开回状态 A 的灵感来源区块（**不清空**下方已有的候选列表）
- 状态 B 点「重新生成」→ 按输入框**当前最新内容**重新生成一轮，**覆盖**下方候选列表
- 候选列表只在生成过至少一次后出现；回到状态 A 不清除它

### 9.3 轴一：灵感来源（聊什么）

三个分类 Tab，**互不共享已抽到的内容**，各自独立缓存：

| Tab | 抽什么 | 抽几条 | 从哪来 |
|---|---|---|---|
| **随便聊聊**<br>（原「水贴」，改名避与回复风格撞车） | 顶级认知 / 冷知识 / 扎心真相 | 各 1 条 = 3 条 | 模型生成（`buildIdeaPrompt`），**不依赖任何页面状态** |
| **Feed热帖** | 当前可见 Feed 里互动量较高的帖子 | 5 条 | `collectTimelineTweets(5)`，只扫已渲染的，不滚动加载 |
| **热点** | X 右侧栏「正在流行」的话题 | ≤10 个 | `collectTrends(10)`，读已渲染的侧边栏 |

抽取与交互规则：

- **面板打开 / 切到某个 Tab 时抽取**（可后台预抽取）。该 Tab 已抽到过就**沿用**，不重复发请求
- 分类行右侧「**⟳ 换一批**」：只重抽**当前激活 Tab**，**不影响其他 Tab**
- **点任意一条 → 把该条文字填入输入框**（面板自己的输入框）。**不直接生成、不跳过输入框**
- 填入后用户可自由编辑，也可直接点「生成帖子」
- **可以完全不选灵感**，直接手动输入
- 灵感列表的样式沿用现在的紧凑列表行（它是"素材"不是"成品"）—— ⚠️ **待确认**

### 9.4 输入框

- placeholder：`想发点什么？（可选，一两句话）`
- 内容来自灵感点选 **或** 用户手输，两者都进同一个输入框，填完可自由编辑
- **输入框为空时，「生成帖子」按钮禁用**（`disabled`，沿用回复模式同款低透明度样式）
- 发帖模式**不再**需要"选题 chip"这套东西——选中即进输入框，比 chip 直接

### 9.5 轴二：风格库（怎么说）

- 5 个风格，**与回复模式的 5 个（观点 / 补充 / 反向 / 简短 / 水贴）完全独立**，不复用、不共享实现逻辑
- 5 个风格（2026-09-15 用户给定）：**观点 / 反直觉 / 提问互动 / 自嘲 / 废话体**

| 风格 | key | 说明（设置页显示） |
|---|---|---|
| 观点 | `post-opinion` | 明确输出一个判断或立场，有主张、不含糊 |
| 反直觉 | `post-counterintuitive` | 抛出一个反常识但站得住的看法，礼貌不抬杠 |
| 提问互动 | `post-question` | 以一个问题收尾，把话筒交给评论区 |
| 自嘲 | `post-selfdeprecating` | 拿自己开涮，松弛、不装 |
| 废话体 | `post-nonsense` | 没什么信息量，但读着顺、有氛围 |

> ⚠️ 旧 key（`post-counter` / `post-trend` / `post-short` / `post-thread`）已废弃。
> `lib/config.ts` 的 `migratePostStyles()` 与 `public/options.js` 的同名函数会检测旧 key
> 并整体重置为新默认——否则旧 5 个会与新 5 个并存变成 10 个风格。
- 用户可在设置里调整**展示顺序**、为每个风格设置**默认生成数量**
- 生成数量总和有上限，沿用回复模式同款规则：`MAX_TOTAL_REPLIES = 10`（`lib/config.ts`）
- 存储：`uiConfig.postStyles`，与 `uiConfig.styles`（回复风格）是**两个独立设置区块**，各自存储、互不影响
