## 1. 需求原文（PROJECT.md §25）

```text
🛡 Clean

识别：Bot / Spam / 重复内容 / 色情引流 / 诈骗 / 赌博引流 / 广告 / 低质量 AI 批量账号

但保留：显示 / 为什么隐藏？ / 永远隐藏此类内容

```

## 2. 用户澄清：先做评论区，不是首页时间线

原始诉求其实是**帖子详情页评论区里的机器人回复**，典型样本：

```text
【应该没人比👆我玩的更开了吧🥑🪄我福不黑不信你看 l 9 ❤】
【应该没人比我玩的开了吧☠️🗯️我福不黑不信你看】
```

因此本模块分两期：

| 期 | 范围 | 状态 |
|---|---|---|
| **A（先做）** | **帖子详情页 → 评论区（回复列表）的机器人 / 垃圾回复** | ✅ 已实现 |
| B（后做） | 首页时间线的帖子清理 | 未开始 |

技术红利：X 详情页里的回复同样是 `article[data-testid="tweet"]`，**选择器可完全复用**，只需排除 URL 对应的那条主推文。

## 3. 已确认的决策（2026-09-15）

| 项 | 决定 |
|---|---|
| 分类策略 | **规则为主，LLM 按需**——本地规则实时跑；只有用户点「为什么隐藏？」时才调 LLM 生成解释 |
| 呈现方式 | **折叠成占位条**，保留「显示 / 为什么隐藏？ / 永远隐藏此类内容」三个操作 |
| 默认类别 | 重复刷屏 ✅ / Bot 僵尸号 ✅ / 色情·赌博·诈骗引流 ✅ / 广告推广 ✅（**低质量 AI 批量账号先不做**，误杀率最高） |
| 白名单 | 豁免**我关注的账号** + **认证账号** |
| 触发方式 | **自动**（进详情页、评论区向下加载时）+ **「🛡 清理」按钮手动重扫** |

## 4. 分类引擎设计（规则为主）

### 4.1 为什么不用 LLM 逐条判

- 评论区无限滚动，实时性是硬约束；逐条问模型跟不上滚动
- 免费额度顶不住（一条热帖几百条评论）
- 模板化 bot 评论表面特征极强，规则足够

### 4.2 判定规则（按顺序，命中即返回）

| # | 规则 | 类别 | 说明 |
|---|---|---|---|
| 0 | 用户标记过「永远隐藏此类内容」 | repeat | 归一化签名命中 `alwaysHideSignatures` |
| 1 | 白名单豁免 | — | 关注的账号 / 认证账号直接放行 |
| 2 | **近似重复刷屏** | repeat | 与同页其它评论**相似度 ≥ 阈值**且组内 ≥ 2 条 |
| 3 | 关键词命中 | adult / gamble / scam / ad | 分隔词表，命中即判 |
| 4 | 机器人账号特征 | bot | handle 以 ≥6 位数字结尾 且（emoji ≥2 或 文本 <40 字） |

### 4.3 关键：近似重复必须用「相似度」，不能比全等

已验算：用户给的两条样本归一化后**并不相等**（A 多一个「更」字），所以「归一化后全等」抓不到：

```text
A 归一化：应该没人比我玩的更开了吧我福不黑不信你看l
B 归一化：应该没人比我玩的开了吧我福不黑不信你看
          ↑ 从第 9 个字符开始分叉
```

正确做法：**字符 bigram Jaccard 相似度 ≥ 0.65**。

**已用样本实测校准**（脚本一次性验证，未入库）：

| 用例 | 相似度 | 期望 | 结果 |
|---|---|---|---|
| A vs B（两条 bot 样本，差一个字） | **0.810** | 判重复 | ✅ |
| C vs D（正常评论但用词接近） | 0.545 | 不判 | ✅ |
| E vs F（「哈哈哈哈」重复语气词） | — | 不判 | ✅ 被护栏挡掉 |
| A vs G、G vs H（无关内容） | < 0.65 | 不判 | ✅ |
| I vs J（正常但几乎逐字雷同） | 0.789 | 判重复 | ✅ |

三条实现要点（都是实测逼出来的）：

1. **归一化要去掉变体选择符**（`\p{M}`）：emoji 的 U+FE0F 会留在字符串里，干扰相似度。去掉后 A/B 从 0.667 提升到 0.810，与正常评论的余量从 0.12 拉大到 0.27
2. **阈值取 0.65**：0.6 时正常评论 C/D（0.545）离阈值只有 0.055，太薄；0.65 仍能抓住 A/B
3. **字符多样性护栏**：`unique(sig)/len(sig) < 0.25` 视为重复语气词（「哈哈哈…」「对对对…」），不参与重复判定——否则「哈哈哈哈哈哈」vs「哈哈哈哈」相似度是 1.0

归一化完成后太短的评论（< 6 字）同样不参与判定。复杂度：可见评论通常 ≤ 60 条，O(n²) ≈ 3600 次比较，可忽略。

### 4.4 辅助信号（样本特征）

用户样本还暴露了这些特征，可作为加权或后续扩展：

- emoji **夹在文本中间**（👆 / ☠️🗯️ / 🥑🪄），不是正常表达习惯
- 「我福不黑不信你看」是**插字规避**的引流话术（正常应为「我不黑不信你看」，插「福」绕过关键词过滤）
- 末尾带无意义字符（`l 9 ❤`）

第一版不作为独立判据，只作为「为什么隐藏」里的说明依据。

## 5. 呈现与交互

命中的评论**不直接删除**，折叠成一条占位条（保留原文，可恢复）：

```text
┌────────────────────────────────────────┐
│ [已隐藏]  重复刷屏 · 与 3 条内容高度重复  │
│ [显示]  [为什么隐藏？]  [永远隐藏此类]    │
└────────────────────────────────────────┘
```

三个操作的语义：

| 操作 | 行为 |
|---|---|
| 显示 | 展开本条，本次会话不再隐藏（不写规则） |
| 为什么隐藏？ | 展示规则命中的理由；**同时按需调 LLM** 给一句人话解释（唯一会产生模型调用的地方） |
| 永远隐藏此类 | 把归一化签名写进 `alwaysHideSignatures`，以后跨页面/跨会话直接隐藏 |

**幂等**：处理过的 article 打 `data-xc-cleaned` 标记。X 的虚拟列表会重排并重复注入同一节点，不打标记会重复处理。

## 6. 数据结构

```ts
type SpamCategory = 'repeat' | 'bot' | 'adult' | 'gamble' | 'scam' | 'ad';

interface SpamVerdict {
  category: SpamCategory;
  reason: string;      // 给用户看的一句话
  signals: string[];   // 命中的关键词 / 特征
}

interface CleanerConfig {
  enabled: boolean;
  categories: Record<SpamCategory, boolean>;
  whitelistFollowing: boolean;   // 默认 true
  whitelistVerified: boolean;    // 默认 true
  alwaysHideSignatures: string[];
  hiddenCount: number;           // 仅统计展示
}
```

挂在 `uiConfig.cleaner`，沿用「types → config 默认值 → options 页 UI → storage.onChanged 即时生效」的既有流程。

`TweetContext` 需新增两个字段供白名单判定：`isFollowing`（用户名区出现 Following / 正在关注）、`isVerified`（`[data-testid="icon-verified"]`）。

## 8. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| **误杀正常评论** | 🔴 高 | 默认折叠而非删除；三个操作随时可恢复；白名单豁免关注/认证账号；重复组要求 ≥2 条 |
| X 虚拟列表重排导致重复处理 | 🟡 中 | `data-xc-cleaned` 幂等标记 |
| 词表误伤（正常讨论含敏感词） | 🟡 中 | 词表保持克制；命中后仍可「显示」；后续可加「只在高严格度下用 LLM 复核」 |
| DOM 操作影响页面性能 | 🟢 低 | 批量处理 + 节流，复用现有 MutationObserver 模式 |
| 隐藏后 X 布局跳动 | 🟢 低 | 占位条占用高度，视觉上不塌陷 |

**红线（PROJECT.md §25 / ARCHITECTURE.md §6）**：只做本地隐藏，**不封禁、不举报、不静音、不取关、不做任何写操作**。
